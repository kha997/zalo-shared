# Private synthetic pilot operations

This is original application code. Owner licensing remains unresolved; no upstream application license is asserted. No live Zalo connector exists. Production acceptance remains closed. PostgreSQL digest was verified by an actual root pull; Node 24.19.0 image digest was also verified by actual pull and pinned in both stages. Digests are not a current security baseline; refresh, scan and record registry digests before deployment. CI action commit identifiers require registry/source verification before relying on supply-chain provenance.

## Start and stop

Requires Docker Compose v2, Node 24 for host tooling, and a generated package-lock.json. Build from repository root. Copy `ops/env.example` to a private file outside the repository, chmod 600, and populate all required values. Generate independent random database password and metrics token; never use example CI credentials. DATABASE_URL uses restricted role `zs_app` at `postgres:5432`; MIGRATION_DATABASE_URL uses POSTGRES_USER owner. Set independent APP_DATABASE_PASSWORD and owner password, URL-encoding credentials. Initial PG volume startup creates zs_app from environment via psql quoted variables. Existing volumes require operator role bootstrap without recreating data. PUBLIC_ORIGIN is exactly `http://127.0.0.1:3100` for this local pilot. No registration/default staff credentials exist.

Use `docker compose --env-file /private/zalo.env -f ops/compose.yaml up -d postgres`, then `docker compose --env-file /private/zalo.env -f ops/compose.yaml run --rm migrate`. Seed using the same one-off command with `-e ADMIN_EMAIL -e ADMIN_PASSWORD` before `migrate`, supplying values through the invoking environment (not literal command arguments). End the command with `node dist/server/seed.js`. Unset seed variables afterwards. Start app with `up -d app`. Worker is opt-in via `--profile dispatch up -d worker`; default provider mode is disabled, including worker. Do not scale worker. Simulator exercises use a separate test environment with NODE_ENV=test, PROVIDER_MODE=mock and MOCK_ENABLED=true; production mock controls are rejected.

App publishes only 127.0.0.1:3100; PostgreSQL has no host port. The internal Docker network denies ordinary external routing. Restrict access to Docker socket/host: they bypass these boundaries. No TLS is provided for local HTTP. A future TLS deployment must use HTTPS PUBLIC_ORIGIN, Secure cookies, trusted same-origin forwarding and an independently reviewed ingress configuration. Never expose the current loopback exception publicly.

Use `stop worker app` to quiesce; `down` preserves database volume. Never use `down -v` against retained data. Only the maintenance-profile migrate service receives MIGRATION_DATABASE_URL owner credentials; app/worker receive runtime DATABASE_URL. Migrate applies grants to APP_DATABASE_ROLE=zs_app and denies audit UPDATE/DELETE/TRUNCATE. Verify these operations fail with runtime credentials. Never grant owner role membership to zs_app. Backup includes private attachment bytes in PostgreSQL, not a separate filesystem volume.

## Health and monitoring

`/health/live` checks process; `/health/ready` checks DB only. A ready API does not imply provider connection or delivery readiness. Poll `/metrics` with Authorization bearer METRICS_TOKEN from a private collector. Optional configuration and coverage gaps are in [ops/monitoring](../../ops/monitoring/README.md); no collector is deployed by default. Keep token out of URLs, logs and screenshots; use a protected collector configuration, rotate by restarting app. Do not label metrics with staff, contacts, message text or tokens.

Alert immediately on any unknown delivery backlog; stop automatic dispatch investigation and reconcile each affected message before an explicit new send. Alert on growing oldest pending age, repeated failures, DB disconnection, readiness failure and worker restart/lock loss. Establish measured baselines and alert thresholds during pilot; initial operational triggers are pending age >60 seconds for 5 minutes, readiness failure twice, and a stale provider event >5 minutes while connected and traffic is expected. Quiet accounts can legitimately have no recent event. Provider status and lastEventAt are available at authenticated `/api/provider`; no generic DB-health check establishes provider freshness. Track queue counts/age, HTTP latency/error rates, DB connections/storage, backup age, restore drill result and host CPU/memory. Record which metrics are actually exported before wiring alerts; missing instruments are an open gate, not zero failures.

## Incident, revoke and reconnect

1. Stop worker first; preserve DB and redacted logs. Record UTC incident window and affected message IDs. Do not export credentials or bodies into public issues.
2. For account/staff compromise, admin disables the staff user and rotates/revokes affected sessions and external credentials; verify existing sessions fail. Revoke provider sessions on the approved account device if a future live adapter exists. This release has no provider login/reconnect API.
3. Classify pending/processing/unknown and compare authoritative provider acceptance evidence. Never resend unknown automatically. A DB lock cannot fence a paused process from a real provider: confirm old worker terminated and its egress revoked before takeover.
4. Repair cause, rotate compromised metrics/database secrets, verify privileges/CSRF/origin, then restart only the API. Re-enable one worker only after operator reconciliation. Retain evidence under access-controlled retention; owner must choose a retention policy before real data.

## Encrypted backup and restore drill

Install matching PostgreSQL 17 clients and age. Maintain an age recipient public key at backup host; keep corresponding identity offline/separately controlled, with an independently tested recovery copy. Encrypt archives and configuration backups; never store identity beside archive. Use PGPASSFILE chmod 600 (libpq variables select endpoint/database/user); do not put credentials in shell argv. Disk must be encrypted: scripts briefly create plaintext files under TMPDIR and remove them on exit; removal is not secure erasure. Set TMPDIR on encrypted private storage with adequate space.

Quiesce app and worker before backup so dump, counts and hashes represent one boundary. Set QUIESCED=yes and AGE_RECIPIENT, run `ops/backup.sh /private/backup.age`; archive includes custom dump, table counts, UTC time and SHA-256 manifest, then age authenticated encryption. Outer checksum detects transfer corruption; authenticated age decryption protects archive integrity. Copy encrypted archive/checksum off host and record last committed transaction boundary. No measured RPO/RTO is claimed; backup cadence and downtime require owner targets.

Restore only on a separate isolated PostgreSQL instance with no app or worker access. Set libpq endpoint variables, AGE_IDENTITY_FILE and RESTORE_QUARANTINE=yes, then `ops/restore.sh /private/backup.age drill_YYYYMMDD` using a lowercase suffix. Script refuses existing DB, revokes PUBLIC CONNECT on fresh template0 DB before restore, verifies ciphertext and inner manifest, restores atomically, compares table counts and content fingerprints, deletes restored sessions, disconnects provider and quarantines pending/processing work as unknown. It never drops an existing DB. Failed restores leave an isolated DB for investigation; choose a new name after remediation. Use only trusted archives generated by backup.sh (tar is not an untrusted upload parser).

Verify attachment byte hashes against source, audit history, actor/role restrictions and authenticated media access; verify every previously sent job stays sent and no restored unknown/pending job dispatches. Keep dispatch profile off and provider disabled. Restored DB CONNECT remains denied to runtime; test zs_app connection rejection. Only after verification and operator reconciliation may owner rerun runtime grants and explicitly GRANT CONNECT for the intended runtime role. Never enable while unknown jobs remain unresolved. Record dump UTC, source boundary, start/end times, bytes/counts/hash results, simulated lost transactions and measured RPO/RTO in a private drill report. Restore application configuration separately; do not restore live sessions or enable dispatch by copying old settings. A successful pg_restore alone is not a completed drill.

## Capacity and live acceptance gate

Record machine resources, dataset, workload, duration, 4/10/25/50 user latency percentiles, errors, message throughput and queue age. Four browser contexts establish session concurrency only. No unlimited capacity or physical workstation claim is supported. Set limits based on measured results and business targets.

Before any live deployment: owner-approved separate test account/device; platform/terms and account restriction risk acceptance; actual phone coexistence; text/media receipt and provider ID tests; disconnect/session invalidation/reconnect soak; provider acceptance crash-window tests; confirmed old-worker fencing; unknown resolution procedure; privileged/disabled-user security review; production runtime DB least privilege; independent security review; dependency and image advisory/digest verification; encrypted restore drill with media hashes and measured recovery; monitoring alerts; retention and incident owners; explicit production authorization. CI builds/tests only and never deploys.

Runtime image uses compiled JavaScript and production dependencies only. tsx/TypeScript/Vite/Playwright remain build/test tools and are removed before the final image is copied. Local `npm start` requires `npm run build`; local development retains `npm run dev`. Image scanning records all high/critical findings and fails on fixable ones; unfixed findings remain an explicit production-risk gate.
