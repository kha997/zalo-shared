# ZaloCRM audit — 2026-10-27

Scope: one personal Zalo account, four staff workstations and existing phone. Source snapshot **d186fd2fd75f886a993e2de0b802e52675dac1f7**, default main branch, public repository vuongnguyenbinh/ZaloCRM. This is a static and synthetic audit; no live Zalo behavior, phone coexistence, account safety or history completeness was validated.

## Recommendation

Architecturally suitable as a shared web inbox prototype: four browser sessions can use one central backend Zalo session, instead of four independent Zalo Desktop logins. It has staff users, roles, account ACLs, PostgreSQL persistence and staff attribution for sends through the CRM. **Do not use unmodified with customer data or expose it publicly.** The Socket.IO confidentiality/authentication failure and unrestricted member account-management routes are release blockers. Message durability, deduplication and reconnection need repairs and controlled acceptance tests. Continued personal-phone operation is an unverified platform/SDK property, not established by these tests.

## Evidence and severity

All source links below are pinned to the audited SHA.

1. **Critical: real-time chat broadcast without authentication.** [app.ts:84](https://github.com/vuongnguyenbinh/ZaloCRM/blob/d186fd2fd75f886a993e2de0b802e52675dac1f7/backend/src/app.ts#L84) constructs Socket.IO without token verification; [zalo-socket.ts:8](https://github.com/vuongnguyenbinh/ZaloCRM/blob/d186fd2fd75f886a993e2de0b802e52675dac1f7/backend/src/modules/zalo/zalo-socket.ts#L8) accepts arbitrary org/account room IDs supplied by the client. [listener:129](https://github.com/vuongnguyenbinh/ZaloCRM/blob/d186fd2fd75f886a993e2de0b802e52675dac1f7/backend/src/modules/zalo/zalo-listener-factory.ts#L129) and [chat-routes.ts:159](https://github.com/vuongnguyenbinh/ZaloCRM/blob/d186fd2fd75f886a993e2de0b802e52675dac1f7/backend/src/modules/chat/chat-routes.ts#L159) broadcast message payloads with io.emit to every connected socket. Browser CORS is not authentication. An unauthenticated mock socket successfully joined arbitrary org/account rooms. Repair must authenticate the handshake, authorize every room and emit only to authorized recipients, including QR and status events.

2. **High: member can manage another staff member's Zalo account within the same org.** [zalo-routes.ts:60](https://github.com/vuongnguyenbinh/ZaloCRM/blob/d186fd2fd75f886a993e2de0b802e52675dac1f7/backend/src/modules/zalo/zalo-routes.ts#L60), :83 and :114 require JWT plus org membership only for login, reconnect and deletion. No owner/admin/account ACL is checked. Deleting an account cascades its conversations/messages through [schema:150](https://github.com/vuongnguyenbinh/ZaloCRM/blob/d186fd2fd75f886a993e2de0b802e52675dac1f7/backend/prisma/schema.prisma#L150) and :177. Member conversation detail and mark-read routes also omit account ACL ([chat routes:67](https://github.com/vuongnguyenbinh/ZaloCRM/blob/d186fd2fd75f886a993e2de0b802e52675dac1f7/backend/src/modules/chat/chat-routes.ts#L67), :169), despite ACLs on message read/send.

3. **High: plain stored session credentials; unsafe secret fallback.** [pool:202](https://github.com/vuongnguyenbinh/ZaloCRM/blob/d186fd2fd75f886a993e2de0b802e52675dac1f7/backend/src/modules/zalo/zalo-pool.ts#L202) saves cookie, IMEI and user agent directly into JSON sessionData ([schema:79](https://github.com/vuongnguyenbinh/ZaloCRM/blob/d186fd2fd75f886a993e2de0b802e52675dac1f7/backend/prisma/schema.prisma#L79)). No encryption occurs in this path. DB backups therefore contain usable session material. [config:9](https://github.com/vuongnguyenbinh/ZaloCRM/blob/d186fd2fd75f886a993e2de0b802e52675dac1f7/backend/src/config/index.ts#L9) falls back to a public JWT signing secret even in production; production should fail startup without a strong configured secret. EncryptionKey configuration alone does not encrypt sessions.

4. **High: no incoming event deduplication or durable ingest queue.** [message-handler:47](https://github.com/vuongnguyenbinh/ZaloCRM/blob/d186fd2fd75f886a993e2de0b802e52675dac1f7/backend/src/modules/chat/message-handler.ts#L47) creates a fresh UUID for every event; [schema:161](https://github.com/vuongnguyenbinh/ZaloCRM/blob/d186fd2fd75f886a993e2de0b802e52675dac1f7/backend/prisma/schema.prisma#L161) has no uniqueness constraint on Zalo message identity. The mock repeated the same msgId twice: two rows, unread increment twice. Contact/conversation lookup, creation, message insertion and unread update are separate DB calls; an error is logged and returns null (:103), with no durable retry in the inspected handler. A DB failure can drop an event; concurrent conversation creation can hit its unique constraint and lose the second message. First inbound conversation starts unreadCount=1 then increments again (:195 and :213), so its unread count can start at two.

5. **High: outgoing send is not atomic or idempotent.** [chat routes:132](https://github.com/vuongnguyenbinh/ZaloCRM/blob/d186fd2fd75f886a993e2de0b802e52675dac1f7/backend/src/modules/chat/chat-routes.ts#L132) sends remotely, ignores returned remote message identity, then inserts local message. A successful send followed by DB failure returns 500; retry may send again. Self echo is independently inserted by listener/handler with no reconciliation, potentially producing local+echo duplicate rows. [frontend:107](https://github.com/vuongnguyenbinh/ZaloCRM/blob/d186fd2fd75f886a993e2de0b802e52675dac1f7/frontend/src/composables/use-chat.ts#L107) unconditionally pushes HTTP response while socket handler deduplicates only by local row ID; socket-first ordering can also duplicate the same row in UI. Four staff can send concurrently; inspected send route has no conversation claim/lock or collision warning. Do not infer external send delivery semantics from these mocks.

6. **High: revocation is delayed.** [auth routes:42](https://github.com/vuongnguyenbinh/ZaloCRM/blob/d186fd2fd75f886a993e2de0b802e52675dac1f7/backend/src/modules/auth/auth-routes.ts#L42) issues seven-day JWTs. [auth middleware:7](https://github.com/vuongnguyenbinh/ZaloCRM/blob/d186fd2fd75f886a993e2de0b802e52675dac1f7/backend/src/modules/auth/auth-middleware.ts#L7) checks signature only, without current isActive/role lookup or token version. Login checks isActive, but an already issued token retains old role until expiry. Staff removal/password rotation must invalidate sessions immediately.

7. **Medium: reconnection exists but is not a proven recovery guarantee.** [pool:117](https://github.com/vuongnguyenbinh/ZaloCRM/blob/d186fd2fd75f886a993e2de0b802e52675dac1f7/backend/src/modules/zalo/zalo-pool.ts#L117) reuses persisted cookie/IMEI; close handler schedules reconnect after 30 seconds and circuit breaker after five closes in five minutes. [listener:159](https://github.com/vuongnguyenbinh/ZaloCRM/blob/d186fd2fd75f886a993e2de0b802e52675dac1f7/backend/src/modules/zalo/zalo-listener-factory.ts#L159) also asks SDK to retryOnClose, creating two recovery mechanisms. Timers are not cancelled by manual disconnect; autoReconnect only skips connected instances. [health-check:21](https://github.com/vuongnguyenbinh/ZaloCRM/blob/d186fd2fd75f886a993e2de0b802e52675dac1f7/backend/src/modules/zalo/zalo-health-check.ts#L21) retries disconnected sessions every five minutes, including after the pool circuit breaker because its instance stays disconnected. Daily refresh disconnects and reuses old credentials (:38); this code alone does not prove refreshed cookies are persisted. No inspected replay cursor/backfill path proves messages during downtime are recovered.

8. **Medium: undo scope is incomplete.** [handler:220](https://github.com/vuongnguyenbinh/ZaloCRM/blob/d186fd2fd75f886a993e2de0b802e52675dac1f7/backend/src/modules/chat/message-handler.ts#L220) accepts accountId but updates all rows matching msgId only. Mock confirms omitted account/conversation predicate. Impact across accounts depends on remote ID uniqueness; correctness should not depend on an undocumented assumption.

## Architecture, persistence, audit and maintenance

- [README:45](https://github.com/vuongnguyenbinh/ZaloCRM/blob/d186fd2fd75f886a993e2de0b802e52675dac1f7/README.md#L45): Fastify backend, Vue web UI, Socket.IO, PostgreSQL, zca-js personal-account adapter. Pool is singleton in-memory Map ([pool:37](https://github.com/vuongnguyenbinh/ZaloCRM/blob/d186fd2fd75f886a993e2de0b802e52675dac1f7/backend/src/modules/zalo/zalo-pool.ts#L37)); use one active backend session owner until a distributed ownership design exists. Four browser clients do not imply four Zalo sessions.
- Users and read/chat/admin account ACL are represented in schema:43–104; middleware enforces a permission hierarchy on selected routes. Passwords use bcrypt cost 12 ([auth service:36](https://github.com/vuongnguyenbinh/ZaloCRM/blob/d186fd2fd75f886a993e2de0b802e52675dac1f7/backend/src/modules/auth/auth-service.ts#L36)). CRM sends save repliedByUserId ([chat routes:150](https://github.com/vuongnguyenbinh/ZaloCRM/blob/d186fd2fd75f886a993e2de0b802e52675dac1f7/backend/src/modules/chat/chat-routes.ts#L150)); phone/self-echo sends cannot be attributed to a staff user by the inspected ingest path.
- ActivityLog table exists ([schema:204](https://github.com/vuongnguyenbinh/ZaloCRM/blob/d186fd2fd75f886a993e2de0b802e52675dac1f7/backend/prisma/schema.prisma#L204)), but inspected authentication, account-management, chat and user-management paths do not create audit entries. Table existence does not establish a complete audit trail. No append-only integrity, retention or export audit was validated.
- [Compose:35](https://github.com/vuongnguyenbinh/ZaloCRM/blob/d186fd2fd75f886a993e2de0b802e52675dac1f7/docker-compose.yml#L35) has persistent PostgreSQL volume and daily local backups with retention (:50). Restore was not exercised. Backups reside on same host and contain session credentials; add encryption, off-host copies, access limits and restoration drills. App port maps 3080 on all host interfaces (:11); no TLS termination is configured here. Production Docker starts with prisma db push ([Dockerfile:36](https://github.com/vuongnguyenbinh/ZaloCRM/blob/d186fd2fd75f886a993e2de0b802e52675dac1f7/docker/Dockerfile#L36)), not reviewed migrations.

## Required acceptance gates after fixes

Then run four simultaneous isolated browser users against a disposable DB, database-outage/restart/reconnect/replay tests, restore drills, message-type coverage and phone coexistence tests using an explicitly authorized sacrificial personal account. Validate missed-history behavior and actual Zalo policy/account risk independently. No production deployment is recommended from this audit.
