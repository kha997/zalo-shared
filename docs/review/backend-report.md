# Backend implementation report

Status: initial implementation, verification pending dependency and PostgreSQL availability. No live adapter, SDK, Zalo account or external delivery exists.

Implemented Fastify API contract with PostgreSQL users/opaque hashed sessions, scrypt passwords, session expiry/revocation, same-origin CSRF mutations, current role checks, admin staff changes and last-admin guard. Shared-workspace staff can view all conversations and linked attachments; only assigned agents may send, supervisors/admins may override. Unread uses per-user cursors. Message pagination is chronological, defaults 50/max100; `before` is the prior page's earliest message UUID and is validated within the conversation. Conversation lists currently bound to 500 results.

Send acceptance commits message/outbox/parts/audit together, locks conversation to serialize assignment/send and key reuse, canonical payload hashes reject changed retries. Inbound IDs deduplicate per conversation/direction. Attachments are private PostgreSQL bytea, at most 5MiB each/5 per send, no URL fetching; MIME signatures checked for PNG/JPEG/PDF and NUL rejected in text. Downloads are attachments with nosniff.

Worker owns a dedicated PostgreSQL connection and account-wide advisory lock, persists processing before simulator invocation, persists each part separately, and quarantines interrupted/ambiguous dispatch as unknown. Disconnected queues remain pending. Mock provider acceptance is a separate durable ledger with stable per-part IDs. The worker never retries unknown jobs; there is currently no operator resolution/reconciliation API. All provider sends are deterministic synthetic inserts, never network calls. Production worker/live enablement deliberately fails closed.

Configuration: DATABASE_URL; HOST (127.0.0.1), PORT (3100), PUBLIC_ORIGIN (http://127.0.0.1:3100), METRICS_TOKEN; MOCK_ENABLED=true only outside production; PROVIDER_MODE accepts only disabled/mock. LOGIN_RATE_LIMIT defaults 10/minute/IP and can be explicitly increased for measured synthetic load. Seed requires ADMIN_EMAIL/ADMIN_PASSWORD (12+ characters), optional ADMIN_NAME/DEMO_SEED. No credentials are committed. Attachments need no media volume beyond database backup.

Verification evidence: test source was written before implementation, but initial `npm test` execution failed because tsx was not installed; therefore this is **not a demonstrated red/green TDD cycle**. Subsequent compile/integration results must be added below once runtime dependencies and database are supplied.

Remaining limitations to review: SQL audit UPDATE/DELETE trigger blocks ordinary statements, but the migration/schema owner can disable it or TRUNCATE; a dedicated least-privilege application DB role is an operations deployment requirement. Advisory locking cannot fence an externally paused stale process from a real provider; no live adapter is enabled. Metrics initially expose queue counts, not latency histograms. Session revocation checks occur at request entry, and a concurrent revocation may race an already authorized in-flight request. No server-side SSE exists (polling is contract default). Retention/cleanup and unknown-resolution operator UI are deferred. Image magic checks are format signatures rather than a full antivirus/decode pipeline. Synthetic pilot only; no production-readiness claim.

Additional local evidence: Node 24 `--check` parsed app/db/worker and integration-test TypeScript successfully. Direct Node config smoke assertions passed: loopback default; public HTTP, live provider, and production mock rejection. These checks do not replace compilation or PostgreSQL integration.
